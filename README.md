# DocSend Slide Deck Downloader
A Chrome extension to download DocSend slides as a PDF.

https://chromewebstore.google.com/detail/docsend-slide-deck-downlo/bgifpnagflkdlbakcljjokaijnmgecnm

## Installation from source

1. Clone this repository to your machine
2. Navigate to `chrome://extensions/` on Google Chrome.
3. Toggle Developer Mode on the top right if not toggled already.
4. Click Load unpacked and navigate to the directory of this repository and select it.

## Usage

Navigate to any DocSend slide deck page and click on the extension icon on the top right of Google Chrome to generate a PDF of the slide deck.

## Privacy and network access

The extension uses HTTPS GET requests to retrieve slide metadata from the current DocSend page and images from DocSend or CloudFront. Requests send no referrer and reject redirects. Image requests omit cookies and other browser credentials; metadata requests retain the existing login cookies for the current DocSend origin. Page query parameters and fragments are excluded from metadata URLs, while signed image URLs are preserved.

PDF generation and saving happen locally. There are no uploads or telemetry. Download servers still receive your IP address, requested paths, and any tokens in the requested image URLs, and may log those requests. The extension does not control traffic generated by the DocSend website itself. Unsupported hosts, HTTP URLs, embedded URL credentials, and custom ports are rejected. A deck that requires image cookies or redirects will fail rather than bypass these restrictions.

The CORS exception applies only to GET fetches from DocSend pages to CloudFront, rather than to CloudFront traffic from other websites.

## Troubleshooting

Failures are logged locally with the prefix `[DocSend Downloader]`, an error code, the operation, and the slide number or HTTP status when available. Diagnostics exclude private URLs, tokens, cookies, document contents, and raw exception messages. Nothing is sent to a logging service.

For metadata, image, or PDF failures, open the DocSend tab's **Developer Tools → Console**. For startup, script injection, or connection failures, open `chrome://extensions`, enable Developer Mode, and click the extension's **service worker** inspection link. A `NETWORK_REQUEST_FAILED` entry can mean a network, CORS, or redirect failure; Chrome's accompanying network error provides more detail. After a failed download, click the extension again to retry.

## Tests

Run the dependency-free regression suite with Node.js 22.7 or newer:

```sh
node --test tests/*.test.cjs
```

The browser smoke test additionally requires Playwright, its Chromium browser, and the `openssl` executable:

```sh
node tests/browser-smoke.cjs
```

If Playwright or Chromium is installed elsewhere, set `DOCSEND_PLAYWRIGHT_PATH` to the Playwright package and `DOCSEND_CHROMIUM_PATH` to the browser executable. The smoke test uses a temporary browser profile, a local HTTPS server, and a temporary self-signed certificate. Fixture hosts resolve to that server and all other hosts are blocked. Certificate checks are relaxed only in this disposable test profile. It checks the real Chrome ruleset, request headers, CORS scope, blocked redirects, PDF output, and diagnostic redaction.
